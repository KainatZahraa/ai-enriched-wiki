# AI Internship Knowledge Base

An internal engineering wiki that documents itself. Interns write short,
structured pages about what they learned — and an automated AI pipeline
enriches each page with a summary, FAQs, a quiz, related topics, and
suggested next learning — so the wiki compounds in value with every new
intern, instead of losing knowledge every time someone moves on.

## The Problem

Every intern learns something new every week — Docker, Git, OAuth — but
that knowledge usually disappears the moment they move on to the next
task. It lives in their head, or in scattered personal notes nobody else
sees. This project turns "write down what you learned" into a lightweight
habit that automatically produces a shared, searchable, growing resource.

## How It Works

Intern learns something
↓
Writes a structured page (What I Learned / Key Concepts / Mistakes / References)
↓
Sets page Status → "Draft"
↓
Automation (n8n) detects the change
↓
AI (Gemini) generates: TLDR, FAQs, Quiz, Related Topics, Suggested Next Learning
↓
Page is updated automatically, Status → "Enriched"
↓
Wiki grows, page by page, intern by intern

## Tech Stack

- **Notion** — the wiki itself, as a structured database (not just free-text pages)
- **n8n** — automation/orchestration layer that watches for new Draft pages and runs the enrichment pipeline
- **Gemini API** (`gemini-flash-latest`) — generates the TLDR, FAQs, quiz, related topics, and next-learning suggestions

## Notion Database Schema

| Property        | Type          | Purpose                                      |
|------------------|---------------|-----------------------------------------------|
| Name             | Title         | Topic name (e.g. "Docker")                    |
| Author           | Text          | Who wrote the page                            |
| Tags             | Multi-select  | Categorization (e.g. `docker`, `devops`)      |
| Status           | Select        | `Draft` → `Enriched`, drives the automation   |
| Content          | Text          | The raw page content (What I Learned / Key Concepts / Mistakes / References) |
| TLDR             | Text          | AI-generated summary                          |
| FAQs             | Text          | AI-generated Q&A pairs                        |
| Quiz             | Text          | AI-generated retention quiz                   |
| Related Topics   | Text          | AI-suggested related pages, grounded in the actual wiki |
| Next Learning    | Text          | AI-suggested topics to study next             |

## Automation Pipeline (n8n)

1. **Notion Trigger** — polls the database for updated pages every minute
2. **IF: Status is Draft** — only proceeds for pages ready to be enriched
3. **Get many database pages** — fetches all existing page titles, used to ground "Related Topics" so the AI can't invent connections to pages that don't exist
4. **Build Prompt** (Code node) — assembles the enrichment prompt from the page content + existing topic list (see [`prompts/claude-enrichment-prompt.md`](prompts/claude-enrichment-prompt.md))
5. **HTTP Request** — calls the Gemini API
6. **Parse Response** (Code node) — parses the model's JSON output and formats it into clean, human-readable text
7. **IF: Parsed OK?** — only proceeds if the AI's response was valid JSON, to avoid ever writing broken data into Notion
8. **Update a database page** — writes TLDR/FAQs/Quiz/Related Topics/Next Learning back into Notion, and flips Status to `Enriched`

The full exported workflow is in [`workflow/wiki-enrichment-workflow.json`](workflow/wiki-enrichment-workflow.json).

## Setup (if reproducing this project)

1. Create a Notion database matching the schema above
2. Create a Notion internal integration, connect it to the database
3. Import `workflow/wiki-enrichment-workflow.json` into n8n
4. Add your Notion credential and a Gemini API key (or swap in another provider)
5. Activate the workflow

## Known Limitations / Next Steps

- Enriched fields are stored as plain text, not structured Notion blocks — a nicer future version could render FAQs/Quiz as native toggle lists or a separate linked database
- Related Topics currently only considers page titles, not content — could be improved by embedding-based similarity search as the wiki grows
- No review/approval step before a page moves to "Enriched" — could add a "Needs Review" intermediate status for quality control
- Currently tested with a small number of pages; behavior at scale (50+ pages) not yet validated
